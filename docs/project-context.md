# Project context

## Product direction

The project starts with an agent-native entry point inspired by image-blaster. Users open the repository in Codex or another capable coding agent and describe an embodied task and its environment, optionally attaching reference images. A separate end-user agent CLI/API is deferred because maintaining two orchestration paths would slow the first implementation.

## Input model

Every request contains two related but distinct layers:

1. Embodied task: actor, manipulated objects, initial state, goal state, and operational constraints.
2. Scene: spatial structure, surfaces, objects, surrounding environment, style, and optional image evidence.

The pipeline should ask for clarification when missing information materially affects task geometry, while tolerating unspecified decorative details.

## Scene construction strategy

- Agents model spatial structure in Blender, including irregular rooms. This is authored geometry, not a fixed room generator.
- Regular and editable objects are preferably modeled with Blender Python.
- Complex curved or organic assets may be generated by an external 3D model and then normalized and placed by the agent.
- World Labs/3DGS can provide optional non-interactive static visual background,
  especially around tabletop scenes, after an explicit evidence and clean-plate gate.
- Interactive, collision-critical, or manipulable objects must remain explicit geometry.

## Agent hierarchy

The Scene Director owns the global scene contract and integration. A Structure Agent creates the whole spatial shell. Room Agents detail bounded regions. Asset Agents are spawned only for difficult assets. A Review Agent inspects structured reports and rendered evidence. Agents exchange scripts and manifests, not concurrent edits to one `.blend` file.

## Feedback and repair

MCP is optional. The baseline loop works headlessly: build, validate, add diagnostic camera/light rigs, render several views, write `report.json`, inspect, repair source, and rebuild. MCP may be used when screenshots and reports are insufficient, but accepted changes must be synchronized back to source.

## Deferred layer

Physics authoring with `pxr`/`usd-core` will be a separate downstream phase. It will eventually configure rigid/dynamic bodies, collision shapes, joints, mass, friction, and damping after modeling is stable. This repository currently reserves export boundaries without implementing those attributes.
